# 0.4.0 — 2026-10-28

## Added

- **`skill://orcid-guide/SKILL.md`** (template `skill://{+path}`): a skill served from `skills/orcid-guide/` through `createApp({ skills })` and shipped in the npm package and Docker image, covering identity-confirmation gates, identifier chains between tools, and raw Solr query syntax.
- **`orcid_get_works`** accepts `work_types` (ORCID's work-type enum, e.g. `data-set`), `year_from`, and `year_to`, and returns `matchedCount`, the filtered total that `offset` and `nextOffset` page over; `workCount` stays the whole record. Under a year filter, undated works drop out and the notice counts them ([#81](https://github.com/cyanheads/orcid-mcp-server/issues/81)).
- **`orcid_get_works` and `orcid_get_peer_reviews`** return a notice when `offset` is at or past a non-zero `matchedCount` or `totalCount`, so an exhausted page reads differently from an empty record ([#81](https://github.com/cyanheads/orcid-mcp-server/issues/81)).

## Changed

- **Count paging replaces the 64,000-byte response budget** ([#79](https://github.com/cyanheads/orcid-mcp-server/issues/79)): `orcid_get_works`, `orcid_get_peer_reviews`, and `orcid_get_research_resources` (`item_limit`) default to 25 per page (was 50); `orcid_search_researchers.rows` (default 20), works, and peer reviews cap at 1,000, research-resource items at 100, resolver rows at 20, each with a notice when clamped. `orcid_get_work_detail` returns every fetched record of the first 100 distinct put-codes; `deferredPutCodes` lists only codes past that cap or absent upstream.
- **`orcid_get_funding`** with `put_code` returns the description whole ([#79](https://github.com/cyanheads/orcid-mcp-server/issues/79)).
- **Enrichment trailers** render search and resolver query echoes (`Query Used`, `Effective Query`) as code spans in `content[]`.
- **Server `instructions`** describe count paging, the works filters, and deprecated-iD handling in place of the budget rules.

## Removed

- **`orcid_get_funding` `description_offset`**: a call with `put_code` and `description_offset` (any value) now fails `invalid_arguments`. Output fields `budgetOverflow`, `funding[].descriptionOffset`, `funding[].descriptionLength`, and `funding[].nextDescriptionOffset` are gone, as is `orcid_get_research_resources` `budgetOverflow`.

## Fixed

- **Deprecated (merged) ORCID iDs** are served as their primary record: record tools and both `orcid://researcher/{orcid_id}/…` resources report the primary iD as `orcidId`/`orcidUri` and compute `selfAsserted` against it, and the notice names both iDs. `orcid_get_work_detail` and `orcid_get_research_resources` re-fetch under the primary iD where ORCID does not redirect ([#80](https://github.com/cyanheads/orcid-mcp-server/issues/80)).
- **`orcid_resolve_researcher`** escapes Markdown in the name its empty-result notice quotes.

## Security

- **HTTP per-request memory leak**: adopting `@cyanheads/mcp-ts-core` 0.13.17+ closes the leak 0.13.16 carried ([cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)). Each request's controller is released when its response ends, so heap no longer grows with request count on the HTTP transport.
