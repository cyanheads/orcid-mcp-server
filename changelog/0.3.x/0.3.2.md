# 0.3.2 — 2026-10-03

## Changed

- **`sources` on every activity record** ([#59](https://github.com/cyanheads/orcid-mcp-server/issues/59)). The six activity tools report who added each item (`name`, `assertionOriginName`, `selfAsserted`) and render a `Sources` line; descriptions and notices no longer call the data self-reported.
- **`otherNames` on `orcid_get_profile` and the profile resource** ([#58](https://github.com/cyanheads/orcid-mcp-server/issues/58)), in ORCID's order, rendered as an `Other Names` line.
- **`orcid_get_profile` names the sections with no public data in a `notice`** ([#40](https://github.com/cyanheads/orcid-mcp-server/issues/40)), since an empty section can be private.
- **Both resources declare typed errors** ([#39](https://github.com/cyanheads/orcid-mcp-server/issues/39)): `invalid_orcid_id` and `profile_not_found`, each with `data.reason` and a recovery hint, matching the tools.
- **`@cyanheads/mcp-ts-core` 0.13.10**: framework-built errors carry their request ID and fill a declared recovery hint, so the `ctx.recoveryFor` forwards are gone. The image installs production dependencies in a cross-arch `deps` stage on Bun 1.4.2 and no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **Packaging**: the npm tarball excludes `dist/*.mcpb`, and the `.mcpb` bundle excludes `docs/idea.md` and `logs/`.

## Fixed

- **`orcid_get_works` returns every identifier in a work group** ([#51](https://github.com/cyanheads/orcid-mcp-server/issues/51)): the preferred version's own, then any that another source holds, such as a PMID beside a Crossref DOI. Group-level `source-work-id`s are skipped.
- **`orcid_get_funding` returns one record per ORCID funding group** ([#56](https://github.com/cyanheads/orcid-mcp-server/issues/56)), so a duplicate deposit counts once in `fundingCount`; distinct award periods across versions are listed in `periods`.
- **`orcid_get_work_detail` keeps a large-collaboration record within the budget** ([#52](https://github.com/cyanheads/orcid-mcp-server/issues/52)). Past 100 contributors it keeps the first 100 plus the researcher's own entries (`contributorCount`, `contributorsTruncated`); a citation over 8,192 bytes is left out and flagged `citationOmitted`.
- **`orcid_search_researchers` caps each response at 64,000 bytes** ([#54](https://github.com/cyanheads/orcid-mcp-server/issues/54)); a cut page returns fewer `rows` and continues from `nextStart`.
- **`ror_id` accepts a bare ID, a `ror.org/` URL, and either letter case** ([#55](https://github.com/cyanheads/orcid-mcp-server/issues/55)), normalized to the form ORCID indexes. A value that is not a ROR ID (`Stanford University`, `grid.168010.e`) or fails its check digits, which only ever matched nothing, is now rejected before any search runs.
- **`orcid_id` accepts a lowercase `x` check digit, `orcid.org/` without a scheme, a `www.` host, a trailing slash, and surrounding whitespace** ([#57](https://github.com/cyanheads/orcid-mcp-server/issues/57)); a shape error no longer also reports a checksum failure. The `orcid://researcher/{orcid_id}/…` resources reject the `https://orcid.org/…` form, which a URI segment cannot carry, and take the bare iD in either check-digit case.
- **A top-level `OR` in `query` keeps its alternatives beside structured fields** ([#61](https://github.com/cyanheads/orcid-mcp-server/issues/61)): the raw query is ANDed as one parenthesized group; an exclusion-only query stays ungrouped.
- **`orcid_resolve_researcher` resolves byline and `Family, Given` names** ([#53](https://github.com/cyanheads/orcid-mcp-server/issues/53)). When the exact phrase finds nothing, it tries byline initials (`J. Doudna`), drops the affiliation, then searches other names; `orcid_search_researchers` matches an initials-only `given_name` by prefix.
- **`orcid_get_peer_reviews` heads a review with its journal ISSN** ([#60](https://github.com/cyanheads/orcid-mcp-server/issues/60)), not the convening organization, which is often the import service (Publons, Clarivate).
- **Entity references named after `Object.prototype` properties stay literal** ([#62](https://github.com/cyanheads/orcid-mcp-server/issues/62)); `&constructor;` no longer decodes to function source.
- **Researcher-written text renders as data in `content[]`** ([#63](https://github.com/cyanheads/orcid-mcp-server/issues/63)): biographies and abstracts as blockquotes, names, titles, and organization names on one line, and a citation in a fence its contents cannot close. `structuredContent` stays verbatim, and the server instructions say to treat this text as data.
- **One 25-second deadline covers every ORCID request in a tool call** ([#64](https://github.com/cyanheads/orcid-mcp-server/issues/64)), so a stalled upstream fails as `Timeout` instead of holding through four fetch timeouts. A refused connection or a non-JSON 2xx body is a retried `ServiceUnavailable`, never `query_failed` or `fetch_failed`.
- **The User-Agent carries the server's actual version** ([#65](https://github.com/cyanheads/orcid-mcp-server/issues/65)) instead of a hand-edited literal.
