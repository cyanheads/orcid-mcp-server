# 0.3.3 — 2026-10-18

## Changed

- **`orcid_get_research_resources`** accepts `put_code` to retrieve allocation items with all operators, identifiers and URLs; detail pages continue with `nextItemOffset` under both 64,000-byte response budgets, with explicit indivisible-record exceptions. Proposal hosts and the first-host alias are preserved ([#69](https://github.com/cyanheads/orcid-mcp-server/issues/69)).
- **Read request caps** accept search/works page sizes through 10,000 and up to 1,000 raw work-detail codes, disclose effective fetch limits, and deduplicate codes before the 100-distinct-code fetch cap ([#72](https://github.com/cyanheads/orcid-mcp-server/issues/72)).
- **Warnings** identify upstream operations with fixed endpoint labels instead of request URLs or raw transport messages.
- **Packaging and tooling** synchronize framework guidance/scripts, pin Bun 1.4.3, prune musl-only Docker dependencies, correct MCP Registry launch metadata, split CodeQL language analyses, and exclude development files from MCPB bundles.

## Fixed

- **DOI/PMID anchors** reject malformed and prefix-only values before search or resolution, retaining supported URL/label normalization and identifier case ([#67](https://github.com/cyanheads/orcid-mcp-server/issues/67)).
- **Affiliation selectors** select each section once and echo unique selectors in caller order without deduplicating distinct appointments ([#68](https://github.com/cyanheads/orcid-mcp-server/issues/68)).
- **Peer review histories** page in upstream order within both 64,000-byte budgets, preserving returned-count semantics, ISSN headings and provenance; `totalCount` and `nextOffset` describe continuation ([#71](https://github.com/cyanheads/orcid-mcp-server/issues/71)).
- **Work-detail continuation** returns every requested distinct code not settled by an admitted work or identified error in request order, including input-cap, byte-budget and absent-upstream-result deferrals.
