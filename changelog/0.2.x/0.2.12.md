# 0.2.12 — 2026-07-27

## Fixed

- **`orcid_get_affiliations` empty records** (#29) — `extractSummariesFromGroup` (`src/services/orcid/normalizers.ts`) now unwraps each `summaries[]` entry by its singular-type key (`employment-summary`, `education-summary`, `invited-position-summary`, `distinction-summary`, `membership-summary`, `qualification-summary`, `service-summary`) before normalizing, instead of passing the wrapper straight through. Every affiliation field — organization, department, role, dates, disambiguated identifier — now populates instead of only `type`. `RawAffiliationGroup`/`RawAffiliationSummaryEntry` (`src/services/orcid/types.ts`) retyped to match the live wrapper shape, and several ORCID date/organization sub-fields are now typed `| null` to match observed nulls rather than omission.
- **`orcid_get_works` / `orcid://researcher/{orcid_id}/works` missing `workType`** (#30) — `normalizeWorkSummary` now reads `raw.type` instead of the nonexistent `raw['work-type']`; `RawWorkSummary.type` replaces the wrong key.
- **`orcid_get_peer_reviews` missing `groupIssn`** (#32) — `normalizePeerReviews` now matches the group external ID by its `issn:` value prefix instead of an `external-id-type === 'issn'` check that ORCID's `peer-review`-typed group identifiers never satisfy, and strips the prefix before assigning `groupIssn`.
- **`orcid_get_affiliations` fabricated "Dates: present"** (#33) — the `format()` date-range line in `get-affiliations.tool.ts` now renders `present` only when a `startDate` anchors it; an affiliation with neither date renders no `Dates:` line at all, matching `structuredContent`.
