# 0.2.9 — 2026-07-16

## Fixed

- **Solr value escaping** (#18) — new shared `escapeSolrValue()` (`src/services/orcid/solr-query.ts`) backslash-escapes the Lucene reserved character set before every structured value (names, affiliations, keywords, ROR IDs, DOI, PMID) is interpolated into a Solr clause, in both `orcid_search_researchers` (`buildSolrQuery`) and `orcid_resolve_researcher`. Previously, embedded quotes broke phrase scoping and punctuation-heavy DOIs (e.g. `10.1002/(SICI)1099-0844(199912)17:4<290::AID-CBF849>3.0.CO;2-P`) triggered an upstream ORCID 500. The raw `query` passthrough on `orcid_search_researchers` stays intentionally unescaped.
- **`orcid_resolve_researcher` dual DOI/PMID anchor fallback** (#19) — when both `doi` and `pmid` are supplied and the combined primary query misses, the anchor-only fallback now retries each supplied anchor independently — DOI first, then PMID — instead of only ever retrying whichever one `anchorType` pointed at from input presence alone. A valid anchor is never discarded because a different, wrong anchor was also supplied; `anchorType` reports whichever anchor actually produced the returned candidates.
- **`orcid_resolve_researcher` institution overlap stopwords** (#20) — `computeInstitutionOverlap` now drops generic organization words (`university`, `institute`, `department`, `national`, `of`, `the`, and similar) from the input affiliation tokens before matching, so a bare "University of X" can no longer mark unrelated institutions as overlapping. A distinctive token match (e.g. `berkeley`) still reports overlap; output stays a plain boolean.

## Security

- **Solr query injection** (#18) — the escaping above closes an injection path where unescaped Lucene/Solr operators (unbalanced quotes, `OR`, `*:*`) in user-supplied name, affiliation, DOI, or PMID values could restructure the query sent to ORCID's Solr backend rather than staying literal.
- **Upstream error body redaction** (#18) — `OrcidService`'s shared fetch path now throws with `captureBody: false`, so ORCID's raw Solr error body — which echoes its internal Solr host and Java exception class names — is no longer forwarded into client-visible `error.data`. Only the request URL, status, and status text remain.

## Dependencies

- `tsc-alias` `^1.9.0` → `^1.9.1`
