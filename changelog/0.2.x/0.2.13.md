# 0.2.13 — 2026-07-27

## Fixed

- **`orcid_resolve_researcher` institution overlap false positives** (#27) — `computeInstitutionOverlap` now requires the shorter content-word sequence to appear as a contiguous run inside the longer one (`sharesWholeRun`), instead of matching any single distinctive token as a substring anywhere in the candidate institution name. Closes the "University of Washington" / "George Washington University" false positive; short forms like "UC Berkeley" still match their full name since the abbreviation's content words remain a contiguous run of it. `institutionOverlap`'s output description updated to describe the new matching rule.

## Security

- **Upstream URL leak on non-404 failures** (#31) — `OrcidService.fetchJson` routes every non-2xx response through a new `upstreamError()` helper that logs the failing URL server-side via `ctx.log.warning`, then strips `data.url` from a copy of the `McpError`'s data before it reaches the client. `httpErrorFromResponse` seeds `data.url` from `response.url` unconditionally, so the fix strips the key rather than omitting a passthrough. Closes the leak across all upstream-calling tools and resources — `orcid_get_profile`, `orcid_get_works`, `orcid_get_affiliations`, `orcid_get_funding`, `orcid_get_peer_reviews`, `orcid_get_research_resources`, both `orcid://researcher/{orcid_id}/...` resources, and both search tools. `orcid_search_researchers` and `orcid_resolve_researcher` also gain a declared `query_failed` error contract with tool-specific recovery text; transient codes (`ServiceUnavailable`/`Timeout`/`RateLimited`) rethrow untouched so the retryable signal survives.
