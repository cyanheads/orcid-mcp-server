# 0.2.10 — 2026-07-16

## Fixed

- **`orcid_get_work_detail` bulk error `putCode`** (#21) — `normalizeBulkWorks` now falls back to regex-extracting the failing put-code from `developer-message` (`extractInvalidPutCode`, single-unambiguous-match only) when the upstream `put-code` field is absent, which is the live API's behavior for the invalid-put-code error class.
- **`orcid_get_work_detail` error contract** (#22) — a whole-request 404 now maps to a declared `profile_not_found` error instead of bubbling the raw upstream `McpError`; a non-`McpError` or non-`NotFound`/`ServiceUnavailable`/`Timeout` `McpError` maps to the previously-unreachable `fetch_failed`; `ServiceUnavailable`/`Timeout` failures keep their original code and `retryable` flag instead of collapsing to `InternalError`.
- **Record-fetch tool recovery hints** (#25) — `orcid_get_profile`, `orcid_get_works`, `orcid_get_affiliations`, `orcid_get_funding`, `orcid_get_peer_reviews`, and `orcid_get_research_resources` now pass `ctx.recoveryFor('profile_not_found')` on their `profile_not_found` `ctx.fail`, so the declared recovery hint reaches `data.recovery.hint` instead of being dropped.

## Security

- **`orcid_get_work_detail` transport-detail redaction** (#22) — bulk-fetch failures now build fresh error data in every branch instead of propagating the caught error uncaught; upstream `url`/`status`/`statusText`/`body` no longer reach the client.
- **HTML-guard URL redaction** (#28) — `assertNotHtml` no longer interpolates the ORCID API URL into its thrown message; the URL is now logged server-side via `ctx.log.warning` only. Closes the leak the record-fetch tools' `throw err` fallback (for any non-`profile_not_found` error) previously bubbled verbatim to the client.
