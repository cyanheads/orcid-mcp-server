# 0.2.2 — 2026-06-04

**BREAKING:** `orcid_get_work_detail` input parameter renamed from `put_code` (single integer) to `put_codes` (array of 1–100 integers). Callers must update their tool invocations. See migration note below.

## Changed

- **`orcid_get_work_detail` input:** `put_code: number` → `put_codes: number[]` (1–100 put-codes, min/max validated). Single round-trip regardless of count. Resolves [#10](https://github.com/cyanheads/orcid-mcp-server/issues/10).
- **`orcid_get_work_detail` output:** response shape changed from a flat work record to `{ orcidId, orcidUri, works: WorkDetail[], errors: WorkError[] }`. Successfully resolved put-codes appear in `works`; not-found or inaccessible put-codes arrive as `errors` entries without failing the whole call.
- **`orcidGetWorkDetail` service method:** replaced `getWorkDetail(orcidId, putCode)` with `getWorkDetails(orcidId, putCodes[])`, using the ORCID bulk works endpoint (`GET /v3.0/{orcid}/works/{code1},{code2},...`).
- **`normalizeBulkWorks`:** new normalizer in `normalizers.ts` for the bulk endpoint response shape (`RawBulkWorksResponse`, `RawBulkWorkEntry`, `BulkWorkResult` types added to `types.ts`).

**Migration:** callers passing `put_code: 123` must change to `put_codes: [123]`. The response shape also changed — read `works[0]` instead of the top-level work fields, and check `errors[]` for any put-codes that could not be resolved.
