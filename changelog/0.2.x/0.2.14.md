# 0.2.14 — 2026-08-24

Framework maintenance. No file under `src/` changed behavior — every client-visible change below is inherited from `@cyanheads/mcp-ts-core` `^0.12.3`.

## Added

- **Test lanes** — `tests/smoke/` (12 tests), `tests/integration/` (22, `toolContractSuite` over every declared error reason on all 9 tools), and `tests/fuzz/` (11). Suite goes 318 → 363.
- **`bun run test:coverage`** — Vitest run with `@vitest/coverage-istanbul`.
- **`resources/subscribe` / `resources/unsubscribe`** — advertised and backed by the framework.
- **`.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`.**

## Changed

- **Tool arguments are strict** — an unrecognized argument key is rejected by name before the handler runs instead of being silently stripped, and the advertised `inputSchema` carries `additionalProperties: false`. Root level only.
- **The advertised `outputSchema` declares the error envelope** — success fields become optional and `error` is declared, so a client that validates `structuredContent` without checking `isError` no longer rejects error results with `-32602`.
- **Advertised JSON Schema is 2020-12**, not draft-07.
- **Tool input-validation failures read as flat `path: message` sentences** rather than a serialized `ZodIssue[]` blob behind an `MCP error -32602:` prefix.
- **HTTP serves MCP protocol revision `2026-07-28`** on every endpoint, alongside the `initialize`-negotiated 2025 revisions. Existing 2025-era clients keep working.
- **An unknown or disabled tool rejects with `-32602`** instead of resolving an `isError` result.
- **A POST with a non-JSON `Content-Type` answers `415`**, not `-32700`.
- **`ctx.log` output also reaches the client as `notifications/message`**, gated by the client's `logging/setLevel`.
- **Vulnerability reports route to `security@caseyjhand.com`** — `.github/SECURITY.md` also asks reporters to redact credentials from reproductions.
- **`MCP_SESSION_MODE=stateless`** in `.env.example`, matching the Dockerfile — `.env.example` documented `stateful` and omitted `auto`, so a source run and the container resolved differently. `GET /mcp` now reports the resolved mode at `server.sessionMode` rather than `auto`.
- **Telemetry** — a failure in output-schema validation, `format()`, or the enrichment merge records as a failed call rather than a successful one, and `mcp.tool.duration` covers the response pipeline, not just the handler.
- **`tsconfig` split** — `tsconfig.json` typechecks `src/` and `tests/` with `noEmit`; `tsconfig.build.json` emits from `src/`. `tests/` is now typechecked for the first time.
- **Docker image on Bun 1.4.0** (both stages, and `packageManager`) — the production install and the OTEL `bun add` both carry `--omit=peer`, so the runtime image no longer ships the framework's optional peer tiers. `engines.bun` stays `>=1.3.0`.

## Fixed

- **`.mcpbignore`** — the `.env*` and `.mcpregistry_*` patterns are un-anchored, so they match at any depth rather than only at the bundle root.
