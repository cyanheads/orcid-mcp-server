# 0.2.16 — 2026-09-16

## Changed

- **`createApp({ sessionMode: 'stateless' })`** declares the HTTP session posture in source. With `MCP_SESSION_MODE` unset the server now resolves to `stateless`; an explicit value still overrides it. The server card at `/.well-known/mcp.json` advertises the resolved mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` (`@cyanheads/mcp-ts-core` 0.13.1/0.13.2, cyanheads/mcp-ts-core#376, cyanheads/mcp-ts-core#387).
- **A tool argument rejection carries `structuredContent.error`** — an undeclared key, wrong type, or missing field returns `isError: true` with `error.code` `-32602` on every transport, inherited from `@cyanheads/mcp-ts-core` 0.12.7 (cyanheads/mcp-ts-core#377).
- **An ORCID HTTP 500 now classifies as retryable `ServiceUnavailable`** instead of `InternalError`, and a 501 fails immediately with `retryable: false` — inherited from `@cyanheads/mcp-ts-core` 0.12.4 (cyanheads/mcp-ts-core#323).

## Fixed

- **A malformed raw Solr query still fails fast rather than retrying as an outage.** ORCID answers a query its Solr backend rejects with HTTP 500 naming `RemoteSolrException`, which the framework's improved 5xx handling above would otherwise retry as a transient `ServiceUnavailable`. `orcid-service.ts` reads that body server-side and reclassifies the match as `InvalidParams`, so `orcid_search_researchers` and `orcid_resolve_researcher` still fail fast with their `query_failed` recovery hint instead of exhausting the retry budget on a query that can never succeed. A genuine outage on any other endpoint, including `orcid_get_work_detail`, keeps the retryable classification above and now retries automatically where it previously did not.
