# 0.2.4 — 2026-06-19

## Fixed

- **`orcid_get_research_resources`** — non-existent ORCID iDs now throw `profile_not_found` instead of returning an empty success. The `/research-resources` endpoint is unique in returning HTTP 200 `{"group":[]}` (not 404) for non-existent iDs, so an empty result was ambiguous; the handler now disambiguates only on the empty path by calling `getPerson` (which 404s), and the existing `catch` remaps that `NotFound` to `profile_not_found`. A populated result already proves the record exists, so the common path adds no extra round-trip. ([#11](https://github.com/cyanheads/orcid-mcp-server/issues/11))
- **`orcid_search_researchers`** — the `start` parameter gains `.max(10000)`, so Zod rejects `start > 10000` before any upstream request. The ORCID Public API rejects `start > 10,000` for unauthenticated requests with HTTP 400; the schema and its description (now `0–10,000`) are back in sync. ([#12](https://github.com/cyanheads/orcid-mcp-server/issues/12))
- **`orcid://researcher/{orcid_id}/profile`** — the resource handler now catches the upstream `NotFound` from `getPerson` and rethrows a clean `notFound`, so the framework no longer serializes `McpError.data` (the raw ORCID endpoint URL and 404 error body) into the JSON-RPC error sent to the client. The original error is preserved server-side as `{ cause }`. ([#13](https://github.com/cyanheads/orcid-mcp-server/issues/13))
